Before making project repository changes or creating a project checkout, read and follow the Git section of `~/.omp/agent/eci-binding-contract.md`.

Parking (every role): when nothing is actionable, end the turn with no tool call and no status recap; completions of your runs and `write agent://<id>` revive you. `wait` only on your own jobs (bash, background, or subagents you spawned) whose result you need and that should finish within about an hour; never `wait`, sleep, or probe (ps, tail, re-read) for other agents or replies: park. As a subagent, park while such jobs run by repeating `wait` instead of ending the turn: omp disposes a subagent left idle past `task.agentIdleTtlMs`, which cancels its running jobs and subagents. Before parking on anything that will not revive you itself (a lock, device, or another agent's process), tell the agent that will see it clear exactly what to watch and to `write agent://<your-id>` when it does, or run the check as your own async job. Under an active goal, before parking block every pending or in_progress todo with what it waits on (none may remain) and keep at least one blocked todo naming what you await, creating one if none exists, since continuation stops only then; on revival, unblock todos whose blocker cleared. Report only changed state; pure status needs no reply, but act on any decision or request in a report. Send a parked owner no status pings or re-requests; still deliver new requirements, corrections, decisions, index lookups, and cancellations. Silence is non-terminal: do not retry or infer a crash.

Processes (every role): before finishing, stop every process your Bash calls started (`&`, nohup, setsid, build daemons) unless the user or your parent agent needs it kept running. Leave shared on-demand servers (adb, gpg-agent, ssh ControlPersist masters) running; they need no report. Run long-lived work as an omp named service or async job. Start build daemons with a short idle timeout (e.g. `bazel --max_idle_secs=300`). Never kill processes you did not start. Report each other kept process (PID, purpose) and each suspected orphan to the user or your parent agent.
